# Staging Lineage Design

Every staging table generated by `migration/gen_ddl_v2.py` (all 126, in
`migration/reconciled/schema_v2.sql`) carries three lineage columns in addition to
the legacy-shaped fields:

| Column | Meaning |
|---|---|
| `_batch_id` | The deterministic batch that loaded the row: `mig-<first 16 hex of the extract file's SHA-256>`. Retrying the same file resumes the same batch. |
| `_source_offset` | Byte offset of the source record inside the extract file. |
| `_raw_hex` | The record's exact source bytes (hex), untouched by decoding. |

Idempotency is enforced by the database, not by application care:
`CREATE UNIQUE INDEX ux_<table>_batch_offset ON <table> (_batch_id, _source_offset)`
plus `ON CONFLICT (_batch_id, _source_offset) DO NOTHING` in the loader — a replayed
batch inserts nothing twice, even if application checkpoints are lost.

Supporting registers (migration 003, schema `mig`):
- `mig.batches` — one row per batch: source file, SHA-256, layout, counts, and the
  exact control totals (loaded records) and source totals (all parseable records).
- `mig.rejects` — every quarantined record: batch, offset, reason, raw bytes.
  Unique on (batch_id, record_offset) so retries do not duplicate the quarantine.
- `mig.job_state` — the resumable checkpoint (next record offset + loaded key set),
  restored from the database at the start of every run.

Checkpoint semantics (engine): an offset is checkpointed once the record has been
fully handled — loaded OR quarantined — because both outcomes are persisted in the
same transaction as the batch row.

Traceability chain for any operational row: operational natural key → transform batch
(`_batch_id` on the staged source rows) → `mig.batches` (file + SHA-256) →
`_source_offset` + `_raw_hex` (the exact source record). Rejected value never
disappears: it sits in `mig.rejects` with its reason, and the reconciliation delta
(source totals − control totals) equals the quarantined value by construction.

Identifier safety in generated DDL: legacy field names that are PostgreSQL reserved
words (a real field is named `NOT`) or contain characters such as `#` (a real field
is `W#`) are double-quoted by the generator. Both defects were found by executing
the DDL against PostgreSQL 16.4 — they were invisible to text inspection.

## Amendment (2026-11-12, second release)
Staging tables no longer carry the legacy files' PRIMARY KEY constraints. A staging
area is an evidence store: the same legacy key legitimately appears across many
batches (re-extracts, corrections), and enforcing the legacy PK aborted whole import
chunks when a later batch contained an already-seen key (found by the 25 MB
benchmark run). Staging identity is exactly (_batch_id, _source_offset) via the
unique lineage index; duplicate natural keys inside one extract are quarantined by
the engine with reasons. The generator (gen_ddl_v2.py) now emits the legacy key as a
comment only.
